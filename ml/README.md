# Synthetic data and demand forecasting

Training data is synthetically generated using realistic household consumption patterns for prototype development. It does not represent real society residents or measured sensor data.

`backend/app/simulation.py` creates 300 virtual households across eight towers, with six household profiles, day/hour/season effects, repeatable variability, and high-use/heatwave/leak events. `ml/train_forecast.py` creates a versioned 180-day dataset of 17,280 synthetic 15-minute observations, fits a ridge-regression seasonal model, chooses its penalty on a chronological validation set, and evaluates once on a final chronological test set. The resulting dataset is `ml/datasets/synthetic-society-15m-v1.csv`; model coefficients, metadata, and test metrics are stored in `ml/artifacts/water-demand-ridge-v1.json`. The forecast API uses this artifact to return 1, 6, 24 and 48 hour forecasts.

On the final chronological synthetic test set, the ridge model measures MAE 43.090 L/hour, RMSE 63.384 L/hour, and MAPE 0.622%. The previous-day same-slot naive baseline measures MAE 185.811 L/hour, RMSE 471.950 L/hour, and MAPE 2.746% on the same test rows. The split is the first 70% for training (12,096 rows), the next 15% for validation (2,592 rows), and the final 15% for testing (2,592 rows). These scores measure prediction against this generator's outputs only. They are not measured against real household meters and should not be presented as field accuracy. The named high-use, heatwave, and leak scenarios adjust the trained baseline for the demo. The leak demo remains an explicit scenario event and is not a confirmed leak detection.

To reproduce the dataset and artifact from the project root, run `python ml/train_forecast.py`. The current model is a transparent seasonal ridge-regression prototype; no XGBoost model or trained anomaly classifier is included. Parquet output is not implemented. The GitHub OIDC deployment workflow publishes the checked-in JSON artifact under its model name and version in private S3; EC2 downloads the copy bundled with each release and mounts it read-only for inference. S3 upload and EC2 download require the AWS infrastructure and GitHub repository variables to be configured first.
